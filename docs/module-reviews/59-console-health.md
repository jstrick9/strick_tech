# 59 — Console health

**New dimension.** Twenty audits inspect the DOM, the network and the rendered
pixels. **None had ever read the console** — the one channel where the browser
itself reports what the application got wrong.

**Audit:** `scripts/audit/console_health.py` · **key:** `console-health` ·
**baseline:** 2 → **0**
**Tests:** `tests/unit/test_132_console_health.py` (13) — 7 fail on revert.

---

## The defect: no favicon, and a PWA manifest pointing at nothing

`GET /favicon.ico` returned **404 on every single page load**. Browsers request
it unprompted, so every visit logged a failure.

Pulling that thread found worse — `manifest.json` advertised:

| Advertised | Existed |
|---|---|
| `/static/icon-192.png` | **no** |
| `/static/icon-512.png` | **no** |
| `/favicon.ico` | **no** |

The app could be installed as a PWA only **without an icon**: a blank tile on
the home screen, for a product whose stated bar is ChatGPT and Claude.

Three icons are now committed, generated by a dependency-free stdlib script
(hand-written PNG chunks + zlib) rather than adding an image library for three
static files — the same constraint `scripts/build_bundle.py` was written under.
`/favicon.ico` has a route at the root, and the head declares all three.

---

## Why it survived 58 module reviews in plain sight

The console carries **~11,000 messages per session**, essentially all CSP
`style-src` refusals.

Those are expected and harmless: `style-src 'self'` refuses the parser-level
`style` attribute, and `00-style-hydrate.js` re-applies each one through the
CSSOM, where CSP does not reach. **Verified directly this batch — of the
visible elements carrying a `style` attribute, 0 had dropped declarations.**
Nothing is broken on screen.

But a console with 11,000 expected lines is a console nobody reads. A 404 on
every page load sat in the middle of it for the entire review.

That is why **NOISE is counted and budgeted as its own number**. It is not
itself a defect. It is *the condition that hides the next one* — so it gets a
measurement, and the ratchet fails if it grows.

---

## Probe design

- **Both channels.** `pageerror` and `console` are separate Playwright events;
  an uncaught exception does not always surface as a console message of type
  `error`. Proven by injecting one: it appeared on both.
- **Enumerated exemptions, not a blanket filter.** A "just ignore errors"
  filter would have hidden the favicon 404 for exactly the same reason the
  noise did.
- **Failed subresources are matched by URL, not message text.**
  `Failed to load resource: ... 404` carries **no URL** in the message, so it
  cannot be matched against the exempt list; the `response` event supplies it.
  Only as many lines are dropped as there were exempt 4xx responses — removing
  them wholesale would have swallowed the very bug this batch found.
